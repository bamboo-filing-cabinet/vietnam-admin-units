# GSO source reconnaissance

Written 2026-07-10. First substantive task of the repo: verify what the
authoritative Vietnamese administrative-unit sources actually expose, before
committing to the data model in the design spec
(`../../../docs/journals/2026-07-10.vietnam-admin-units-design.md`, monorepo).

**Method:** web reconnaissance of the GSO/NSO endpoints and the surrounding
open-source ecosystem. Endpoint request/response shapes are **not yet
exercised from code** — that is the next task. Treat SOAP method params and
history-export formats as "to confirm against the live service."

## TL;DR

The design's core assumption **holds**: the government exposes both a
**current snapshot** (SOAP service) and a **change-history with effective
dates + decision references** and **point-in-time queries** (the Lịch Sử page).
So the entity + validity + lineage model is buildable from official data —
snapshots as membership input, the history as the lineage/edge input.

Two things to flag up front:
1. The **domain has both `gso.gov.vn` and `nso.gov.vn` forms** (GSO was renamed
   National Statistics Office). Confirm the canonical host in code.
2. The **SOAP service returns current state only**; history lives on the
   `Lich_Su_Moi.aspx` surface. They are complementary, exactly as the design's
   "snapshots + change-history as inputs" anticipated.

## Source 1 — SOAP service (current snapshot)

`https://danhmuchanhchinh.nso.gov.vn/DMDVHC.asmx` (WSDL at `?WSDL`).

Three web methods — one per tier:

| Method | Tier | Params (per service page) |
| --- | --- | --- |
| `DanhMucTinh` | province (tỉnh/thành phố) | none shown |
| `DanhMucQuanHuyen` | district (quận/huyện) | none shown |
| `DanhMucPhuongXa` | commune/ward (phường/xã) | none shown |

Notes / to confirm live:
- The service page lists no parameters, but prior art (`VietThan/DanhMucHanhChinh`)
  calls all three "with the most expansive parameters" — so there likely *are*
  optional filter params (e.g. by parent code). Confirm from the WSDL.
- Default namespace is still `http://tempuri.org/` (unchanged ASP.NET stub) —
  cosmetic, but a marker that this is a plain ASMX SOAP endpoint.
- **`DanhMucQuanHuyen` (district) is significant for us:** the July 2025 reform
  abolished the district tier (3-level → 2-level, Province → Ward). Whether this
  method now returns empty, returns former districts, or errors tells us how the
  service represents the abolished tier. **Must test.** (Design decision stands
  regardless: districts are first-class former entities with `valid_to` = reform
  date.)

## Source 2 — Lịch Sử page (history + point-in-time)

`https://danhmuchanhchinh.nso.gov.vn/Lich_Su_Moi.aspx`

This is the source that makes the temporal model possible. It provides:

- A table with columns: **code, name, English name, level (tỉnh/huyện/xã), and
  Nghị định/Nghị quyết reference + date** — e.g. `202/2025/QH15 - 12/06/2025`
  (the resolution and its effective date). This is the **lineage/edge input**:
  change events tied to official decisions and dates.
- **Point-in-time picker** ("Thời điểm") → retrieve the hierarchy as of a chosen
  date. This is the **snapshot input** for historical eras (e.g. the 2021
  63-province state) without needing archived third-party dumps.
- **From/To date range** ("Từ ngày" / "Đến ngày") and **level filters**.
- **"Xuất Excel"** export → downloadable data.

Related history surfaces seen in prior art: `NghiDinh.aspx` (decrees list) on
the `gso.gov.vn` host.

**To confirm live:** whether point-in-time and history are reachable
programmatically (querystring/postback params, or only via the Excel export),
and the exact Excel schema. This determines whether ingest scrapes, drives the
export, or calls an underlying endpoint.

## Implications for the design

Confirmed / unchanged:
- **Temporal model (entity + validity + lineage) is viable from official data.**
  Lịch Sử supplies both point-in-time snapshots and dated, decision-referenced
  change events — better than the name-inference the `vietnam-elections-wikidata`
  lao-cai reference file had to resort to.
- **`local_id` spine + time-scoped `gso_code`** is right: the reform reshaped
  codes (2-level restructure), so codes are not cross-era stable.
- **District tier first-class with `valid_to`** is right and testable against
  what `DanhMucQuanHuyen` now returns.

Newly surfaced, to fold into planning:
- **Host ambiguity** `gso.gov.vn` vs `nso.gov.vn` — pick and pin the canonical
  base URL in code; keep the other as fallback.
- **Two ingest paths, not one:** SOAP for the current snapshot; Lịch Sử
  (export or endpoint) for history. Plan both.
- **Reuse, don't rebuild:** start ingest from `VietThan/DanhMucHanhChinh`;
  cross-check lineage against `vietnamadminunits`; validate schema against
  `vietnam-provinces`.
