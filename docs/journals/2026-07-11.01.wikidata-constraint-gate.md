# Wikidata constraint gate — province batch passes

Written 2026-07-11. The pre-upload check (DESIGN "remaining items"): do the
properties our batch emits accept the qualifiers/references we attach? Checked
live via the new `vn_admin_units.constraints` tool (allowed-qualifiers constraint
`Q21510851` on each property). Motivated by the P39/P1107 violation precedent
(`.07`).

## Result: PASS — no allowed-qualifiers violations

Our qualifier on the lineage edges is **P585 (point in time)**; references are
**S854 (reference URL)**.

| Property | How we use it | Allowed-qualifiers constraint | Verdict |
| --- | --- | --- | --- |
| `P576` dissolved | date as **value** (+ S854) | none declared | ✅ |
| `P7888` merged into | item value + **P585** qual (+ S854) | none declared → any qualifier OK | ✅ |
| `P1366` replaced by | item value + **P585** qual (+ S854) | declared; **P585 is in the set** | ✅ |
| `P1365` replaces | item value + **P585** qual (+ S854) | none declared | ✅ |
| `P571` inception | **0 emitted** in this batch | declared; P585 **not** allowed | ✅ n/a |

- References (`S854`) are not governed by allowed-qualifiers and are universally
  valid — no issue.
- Value types are satisfied by construction: `P7888`/`P1365`/`P1366` get item
  QIDs; `P576`/`P571` get date values.

## Caveat carried to Phase 2

**`P571` (inception) does not accept `P585` as a qualifier** (its allowed set is
dates-as-value territory: P580/P582/P577 etc., plus P1365). This is fine for us
because we emit inception as `Q… P571 +date` (date is the *value*), never as a
P585 qualifier. Phase 2 (ward tier) creates new items with `P571` — keep the date
as the value there too; do **not** add `P585` on `P571`.

## Tooling

`vn_admin_units.constraints` — reusable, reuses the backoff-aware fetcher:

```
uv run python -m vn_admin_units.constraints            # our batch's props
uv run python -m vn_admin_units.constraints P1365 P7888
```

Reports, per property, the allowed qualifier set and whether a given qualifier
(default `P585`) would violate. Re-run for any new property before emitting it
(e.g. `P518`/`P1107` for partial-share ward lineage in Phase 2).
