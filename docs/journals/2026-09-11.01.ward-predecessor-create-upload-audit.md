# Ward predecessor CREATE upload audit

**Date:** 2026-09-11

This entry records a pre-upload audit of the two QuickStatements files that the
exhaustive predecessor review produced, and the two defects it found. Both
defects are fixed. No Wikidata write or upload was performed.

## Scope

- `statements/na-wards-create-predecessors.qs` — 2,914 `CREATE` blocks.
- `statements/na-wards-create-current.qs` — 1 `CREATE` block.

The emitter already reported `upload_ready=true`. That gate does not cover
either defect below.

## Defect 1: repeated label and description pairs

Wikidata refuses two items that share a label and a description in the same
language. Three pairs of blocks carried an identical Vietnamese label and
description:

| Label | Two items |
|---|---|
| Thị trấn An Lão | `w-1031501-base` (Hải Phòng) and `w-21609-2007-04-26` (Bình Định) |
| Thị trấn Vĩnh Thạnh | `w-21786-2005-11-30` (Bình Định) and `w-31232-2007-01-31` (Cần Thơ) |
| Thị trấn Châu Thành | `w-7090901-base` (Tây Ninh) and `w-8170501-base` (Trà Vinh) |

The manifest guard used `(name_vi, parent_qid, type_qid)`, which separates the
two An Lão districts by QID. The description, however, named only the district,
so two districts that share a name produced the same text. The guard did not
protect the pair that Wikidata constrains.

Fix: `_description` now appends the province when the district name is not
unique across `mappings/districts-qid.csv`. That rule is stable, because it
depends on the district set rather than on the current manifest. It rewrote 108
of 2,914 descriptions and left the other 2,806 unchanged. `build_manifest` now
also rejects any repeated `(name_vi, description_vi)` pair.

## Defect 2: wrong parent district item

Thirteen blocks carried a `P131` that pointed at a same-named district in
another province:

| Ward district code | Correct item | Emitted item |
|---|---|---|
| 708 Huyện Châu Thành, Tây Ninh | Q5088023 | Q5088017 (Long An) |
| 877 Huyện Châu Thành, Đồng Tháp | Q5088012 | Q5088022 (Tiền Giang) |
| 892 Huyện Châu Thành, An Giang | Q1927178 | Q5088015 (Kiên Giang) |

`_district_parent` preferred a lookup by district name plus the entity's
province echo code. That echo can carry the **2025 successor** province code,
while `districts-qid.csv` records the **pre-2025** code. Long An and Tây Ninh
merged under code 80, Tiền Giang and Đồng Tháp under 82, and Kiên Giang and An
Giang under 91, so the name-plus-code lookup silently reached the wrong
district. The six affected wards were Tây Ninh wards mapped to the Long An
district, and so on.

Fix: the ward's own district code is now the primary key, because it is
unambiguous. The district name only narrows a code that maps to more than one
item, and a name-only lookup remains the fallback for a code the mapping does
not carry. The province used in a description now comes from the resolved
district row, not from the entity echo.

The affected wards are `w-7090901-base`, `w-7090902-base`, `w-7090903-base`,
`w-7090913-base`, `w-7090915-base`, `w-7090919-base`, `w-8032105-base`,
`w-8032111-base`, `w-8051901-base`, `w-8051905-base`, `w-8051907-base`,
`w-8051913-base`, and `w-8051915-base`. The six district QIDs were confirmed
against live Wikidata descriptions.

## What the audit verified as correct

- 2,914 blocks of six lines each; every block carries exactly `Lvi`, `Dvi`,
  `P31`, `P17`, and `P131`.
- The statements match the manifest one to one in order and content.
- 455 phường, 366 thị trấn, and 2,093 xã, matching the manifest type counts.
- `P17` is Q881 in every block. All three statements in a block share the same
  `S854` reference. 34 distinct resolution URLs, all `https`.
- 652 distinct `P131` values after the fix, all present in
  `mappings/districts-qid.csv` or `mappings/provinces-qid.csv`.
- No quote, tab, or backslash inside a label or description. Labels reach 30
  characters and descriptions 82, both far under the Wikidata limit.
- No manifest row already holds a QID, and every row has `valid_to`
  2025-06-30.
- No proposed pair collides with an existing item. A SPARQL query returned all
  7,955 Vietnamese label and description pairs for items typed as ward,
  commune, or township in Vietnam; none matches a proposed pair, and none uses
  the phrase `giải thể năm 2025`.
- The `Phường X` label style matches this project's own uploaded batches. Of
  the 360 prefixed items in that set, 140 are its earlier creations.
- The absence of `P576` and `P1366` is deliberate. Journal
  `2026-09-04.01` defers dissolution and succession to the lineage package.
- The current file is clean, and its pair does not exist on Wikidata.

An unscoped scan for the description phrase across all of Wikidata returned
HTTP 429, so the collision check is bounded to items typed as ward, commune, or
township in Vietnam.

## Regression tests

`tests/test_ward_emit_predecessor_create.py` gains three tests:

- the ward district code wins over a same-named district in another province;
- a repeated district name produces two different descriptions; and
- `build_manifest` refuses to emit when it cannot disambiguate.

## State after the fix

All ten reconciliation and emission artifact checks pass. The emitter reports
`upload_ready=true` and passes `--require-upload-ready
--max-preflight-age-hours 24`. The complete repository test suite passes
292 / 292. The manifest still holds 2,914 items across 652 former districts.
No Wikidata write or upload was performed.
