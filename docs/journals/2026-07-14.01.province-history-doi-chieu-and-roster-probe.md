# Province-history probe — Đối Chiếu (Cấp=Tỉnh) + SOAP roster walk

Written 2026-07-14. Scouting the province tier back to 2002 to ground Phase 1b
(the province-history half of Phase 1). Two instruments probed: the Đối Chiếu
crosswalk at **Cấp=Tỉnh**, and a yearly **SOAP `DanhMucTinh` roster walk**. Also
records the correction of an earlier mischaracterization of the 2004 splits.

## Đối Chiếu at province level (`Doi_Chieu_Moi.aspx`, Cấp=Tỉnh)

- **Cấp combo value for Tỉnh = `1`** (Huyện=`2`, Xã=`3`). Same DevExpress controls
  as the district fetcher (`crosswalk_fetch.py`): `cmbCap`, `txtNgay`/`txtNgayDC`
  (`SetDate`), `chkCheck` (Có thay đổi), `cmdThucHien`, `cmdExcel`.
- **Historical province windows use a 9-column positional layout** —
  `base_ma, base_ten, base_ND, base_hieuluc, succ_ten, succ_ma, succ_ND,
  succ_hieuluc, ghi_chu`. This is **wider than the 7-column *named* reform-window**
  layout that `crosswalk.read_province_crosswalk` parses (`DoiChieu_Tinh_2025.xls`).
  ⇒ a **new positional 9-col province reader** is needed (analogous to
  `read_district_crosswalk`), keyed by index not header.
- **2004 code floor confirmed for provinces** (as for districts, `.15`/`2026-07-13.02`):
  any base date ≤ 30/06/2004 returns only the `"Chuyển đổi mã đơn vị hành chính
  2002 - 2004"` code-remap (3-digit→2-digit), ignoring the compare date. Province
  events only appear once the compare date is post-30/06/2004.
- **Decree column is unreliable** (as for districts): rows carry a *later*
  "last-touching" decree — e.g. the Hà Nội / renumber rows show the **2025** reform
  decree `202/2025/QH15` / `1656/NQ-UBTVQH15`, not the 2004/2008 instrument. ⇒
  **source decree numbers externally** (Nghị định / Nghị quyết list) by unit + date.
- **Stale-DOM contamination is severe.** Switching Cấp and re-running via DoClick
  does *not* clear the grid; DOM scrapes pick up hundreds of leftover ward rows
  (e.g. an 800-row Xã remnant bleeding into a Tỉnh query). Distinguish by column
  count (province=9, ward=13) as a stopgap, but the reliable path is the **Excel
  export** (clean server-side file) — the fetcher must use it, not DOM scrape.

### The 2004 event, as GSO records it (base 01/01/2004 → compare 01/01/2005)

All three 2004 "splits" are **carve-outs: the named province persists (code-remapped),
one new province separates off.** No province is dissolved in 2004.

| old (2002, 3-digit) | → new (post-30/06/2004, 2-digit) | new carve-out child (blank base) |
| --- | --- | --- |
| `301 Tỉnh Lai Châu` | `12 Tỉnh Lai Châu` (continues) | `11 Tỉnh Điện Biên` |
| `605 Tỉnh Đắk Lắk` | `66 Tỉnh Đắk Lắk` (continues) | `67 Tỉnh Đắk Nông` |
| `815 Tỉnh Cần Thơ` | `92 **Thành phố** Cần Thơ` (continues + **retype**) | `93 Tỉnh Hậu Giang` |

**Correction to an earlier claim.** Lai Châu was initially (wrongly) described as
a "division where old Lai Châu ends." GSO maps **old Lai Châu (301) → current Lai
Châu (12)** as a continuation; **Điện Biên is the new carve-out**. So Lai Châu is
the same shape as Đắk Lắk / Cần Thơ — parent persists, child carves out. (Factual
nuance that made it tempting to call a division: old Lai Châu's capital Điện Biên
Phủ went to Điện Biên, and current Lai Châu is the smaller remnant. GSO's structured
continuation link is the anchor per the identity model; verify WD's modeling at
reconcile time.)

**Split parentage is *not* in Đối Chiếu.** The carve-out children appear as
blank-base "new" rows with no link back to their parent (a consequence of the 2004
floor). The parent pairing (Điện Biên←Lai Châu, Đắk Nông←Đắk Lắk, Hậu Giang←Cần Thơ)
comes from the **decree** (see below), not the crosswalk.

### The 2008 Hà Tây merger (base 01/01/2008 → compare 01/01/2009, changes-only)

Clean **2-row** province event:

| base | → successor | eff. date | Ghi Chú |
| --- | --- | --- | --- |
| `28 Tỉnh Hà Tây` | (dissolved) | | **"Sáp nhập vào Thành phố Hà Nội"** |
| `01 Thành phố Hà Nội` | `01 Thành phố Hà Nội` (survivor) | **01/08/2008** | (blank) |

Maps directly onto the existing `merged_into` model: Hà Tây ends (`P576`,
`P7888`/`P1366`→Hà Nội), Hà Nội persists (`P1365`→Hà Tây), `P585` = 2008-08-01.
At province level only Hà Tây fully merges (the partial Hòa Bình/Vĩnh Phúc/Phú Thọ
transfers are district/ward-level, not province events).

## SOAP roster walk (`DanhMucTinh`, yearly)

Canonical `fetch_provinces(den_ngay)`; diffed `(name, type)` year-over-year:

```
2002-01-01: 61   2003-01-01: 61   2004-01-01: 61   2004-07-01: 64   2005-01-01: 64
```

- **2002 → 2004-01: genuinely eventless** at province level (61 stable, no name/type
  change). Confirms there is nothing to recover in the pre-2004 window — the 2004
  floor blinds Đối Chiếu there, but the roster walk shows there were no province
  events to miss.
- **2004-01 → 2004-07:** the 3 carve-out children appear (Điện Biên, Đắk Nông, Hậu
  Giang) and **Cần Thơ retype** surfaces as a name change (`Tỉnh Cần Thơ` →
  `Thành phố Cần Thơ`).
- **Data-quality catch:** a **false** event — `Tỉnh Hòa Bình` vs `Tỉnh Hoà Bình`
  (tone-mark orthography variant `Hòa`/`Hoà` in GSO's own data), not a real change.
  ⇒ **name comparison must normalize** (NFC + consistent tone-mark placement) with
  a logged variant list, or the roster walk invents phantom events.

**Implication:** the yearly SOAP roster walk (name/type-normalized diff) is the
**authoritative, Đối-Chiếu-independent event-discovery + cross-check** for the
province tier, and the *only* instrument that sees 2002→2004. Đối Chiếu windows
supply the lineage/prose/effective-dates from mid-2004 on.

## External source cached — NQ 22/2003/QH11

The authority for the 3 carve-out pairings (which Đối Chiếu omits) is **Nghị quyết
22/2003/QH11** (Quốc hội khóa XI, kỳ họp 4, ngày 26/11/2003; hiệu lực 2004-01-01),
*"Về việc chia và điều chỉnh địa giới hành chính một số tỉnh."* Điều 1 divides Cần
Thơ, Đắk Lắk, Lai Châu exactly as above. Cached verbatim:

- `data/raw/decrees/nq-22-2003-qh11.html` + provenance in `data/raw/manifest.jsonl`
  (source: thuvienphapluat.vn 51694; sha256 recorded). Note: thuvienphapluat's HTML
  doubles some Vietnamese chars (e.g. `ngưười`) — a rendering artifact; use clean
  canonical names for derived data.
- Effective **date discrepancy**: legal date **2004-01-01** (decree) vs GSO
  service-date **30/06/2004** (roster). Use the **legal date** for `P571`/`P585`.

## Takeaways for the Phase 1b design (`DESIGN-phase1b.md`)

1. Generalize `crosswalk_fetch.py` to `--tier province` (Cấp=`1`, Excel export).
2. New 9-col positional province crosswalk reader.
3. Yearly SOAP roster walk 2002→2025 as event-discovery backbone; name normalization.
4. Relation set: recode + retype (same-entity attribute changes), carve-out
   (`P807`), absorption (`P576`/`P7888`/`P1366`/`P1365`). No "division."
5. Decrees sourced externally by unit+date; NQ 22/2003/QH11 cached for the carve-outs.
