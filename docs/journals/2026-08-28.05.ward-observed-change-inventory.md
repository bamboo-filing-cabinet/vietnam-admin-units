## Comparison semantics

`vn_admin_units.ward_observed_changes` NFC-normalizes text and collapses source
whitespace, then exact-deduplicates normalized rows. It compares unambiguous
national ward codes across adjacent observations and reports:

- explicit additions and removals;
- same-code field changes split into ward name, tier, district parent, and
  historical province-echo categories;
- exact source conflicts and duplicate national codes as anomaly transitions;
  and
- source paths plus decoded-content hashes on every interval.

A same-code match is deliberately marked
`identity_inference = none_same_code_observation_only`. This matters at the
2025 reform boundary, where code reuse must not be interpreted as proof that
the pre- and post-reform wards are the same entity. Historical `MaTinh` and
`TenTinh` values are labeled as SOAP echoes and remain observation provenance,
not date-correct parent assertions.

## Source anomalies retained

Fifty-two snapshots contain a source anomaly. The artifact preserves all
variants and excludes the affected code from ordinary additions, removals, and
same-code changes until the source becomes unambiguous:

- `7070901` has conflicting tier values in the 2002 and 2004-01 snapshots;
- `09886`, `10117`, and `10123` each appear under two district identity keys
  from 2006-02-09 through 2008-07-02; and
- `09541`, `09595`, `09601`, and `09607` have conflicting name or tier variants
  in eight 2008 Hà Tây snapshots.

Those episodes produce 15 explicit anomaly transitions. They are auditable
source behavior, not silently normalized administrative changes.

## Boundary checks

The first interval, `2002-01-01 → 2004-01-01`, is byte-identical and has no
normalized change. The next interval captures the old-to-national code-scheme
transition as 10,750 additions, 10,537 removals, and one anomaly resolution;
it is not guessed into 10,537 identity edges.

The already audited `2025-06-30 → 2025-07-01` boundary is independently visible
as 3,316 same-code changed observations, five additions, and 6,719 removals.
Those counts agree with the boundary artifact while retaining the stricter
non-identity interpretation needed for the historical inventory.

## Ledger integration and storage

`data/ward-source-coverage.json` is now schema version 2. It fingerprints the
observed-change artifact, materializes 179 compact event records, and lists all
179 under `unreconciled_event_ids`. Their crosswalk evidence and legal
instrument lists remain empty on purpose; Task 4 and Task 6 fill those links.
The ledger now reports
`event_inventory_status = complete_pending_task_4_crosswalk_reconciliation`.

The derived JSON remains plain rather than separately gzipped. It is below
GitHub's file-size limit, stays directly inspectable and diffable, follows the
repository's existing derived-data convention, and Git compresses the stored
object and transfer. Deterministic gzip remains reserved for the verbatim SOAP
raw-cache artifacts where the manifest records both stored and decoded hashes.
