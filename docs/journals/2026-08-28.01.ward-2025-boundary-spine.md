## Missing source recovered

structured-link source, but its notes are sparse. The live NSO page was queried
in the opposite direction:

```text
uv run --group ingest python -m vn_admin_units.crosswalk_fetch \
  --tier ward --window 01/07/2025 27/08/2026
```

That produced:

- `data/raw/crosswalk/ward_2025-07-01_2026-08-27.xls`;
- 2,357,429 bytes;
- SHA-256 `93957d3aee86447cea61d765cdeb8ae9346e22aa17f7e2a374283e62f51d82cd`;
- 3,321 rows, one for every post-reform unit; and
- a non-empty `Ghi Chú` on every row.

The direction is decisive. With the post-reform roster on the base side, each
successor carries its defining composition narrative. Example `00004` names
Quán Thánh, Trúc Bạch, and the partial contributors to the new Ba Đình. The
window also records the ten 2026-04-30 Đồng Nai type/name changes on the compare

The source still has a hard limit: 20 narratives contain exactly 255 characters
before the appended `. Bỏ cấp huyện` suffix, and several end mid-name. Those
rows need the corresponding provincial resolution annex during full

## SOAP province fields are a current-record echo

The first strict build failed at ward `02635`, which exposed a systematic source
behavior. In a historical `DanhMucPhuongXa` response, the ward and district
fields are dated, but the province code/name can echo the current province row.

Against the date-correct old-side crosswalk:

- 999 of 10,035 pre observations have a different SOAP province code;
- the differences form exactly seven old→current code pairs:
  `15→10` Lào Cai (151), `24→27` Bắc Ninh (121), `44→45` Quảng Trị (119),
  `52→64` Gia Lai (218), `80→72` Tây Ninh (94), `82→87` Đồng Tháp (141), and
  `91→89` An Giang (155); and
- 159 SOAP province labels say `Thành phố Đồng Nai` where the dated crosswalk
  says `Tỉnh Đồng Nai`, reflecting the later 2026 type change.

The artifact therefore uses the crosswalk's base province as the dated
`province_code`/`province_name_vi`, while preserving SOAP's values as
`soap_province_*_echo`. The pre-reform district code/name still comes directly
from SOAP; that is the crosswalk's missing disambiguation key and has complete
coverage.

## Normalization and one correction

`ward_model.normalize_snapshot` applies NFC + whitespace normalization to
derived rows, collapses only exact duplicates, and raises on conflicting rows
sharing `(MaTinh, MaQuanHuyen, MaPhuongXa)`. The raw bytes are never modified.

The post-reform SOAP roster has one blank label: code `00070`. The build fills
it as `Phường Hoàn Kiếm` from the same official NSO composition export and logs
the source path/value in `corrections`. No other name is overwritten; spelling
differences remain visible source evidence for the later normalization pass.

## Hard gates and verification

The build rejects:

- any raw artifact that fails its manifest hash;
- a conflicting normalized SOAP identity;
- duplicate national ward codes at either boundary;
- missing/duplicate composition rows or empty composition notes;
- a structured endpoint absent from its SOAP boundary roster;
- a post-reform SOAP pseudo-parent code different from its province code;
- a successor effective date other than `2025-07-01`; or
- any drift from the locked 10,035 / 3,321 / 3,316 / 5 / 6,719 counts.

Six new focused tests cover normalization, exact duplicate collapse, conflict
rejection, source counts, the `00070` repair, endpoint uniqueness, composition
ground truth, the 255-character source limit, province-echo audit counts, and
deterministic output. Full suite result: **153 passed**.
