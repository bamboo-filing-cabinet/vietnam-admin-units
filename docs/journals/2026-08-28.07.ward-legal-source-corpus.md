## Acquisition and validation contract

The fetcher groups the 453 high-recall legal-index rows into the locked 449
`<normalized code>@<effective date>` keys and then:

1. searches the appropriate Government document class by exact code;
2. falls back to high-similarity title search when the index code is malformed
   or the portal's exact-code search misses an archived record;
3. validates normalized code, issue/effective-date order and gap, title
   similarity, allowlisted HTTPS hosts, and attachment URLs;
4. downloads and reparses the detail page, rejecting metadata or attachment URL
   drift between discovery and preservation;
5. validates each original by byte signature rather than trusting its suffix;
6. writes verbatim bytes through `rawcache`, with URL, source class/role,
   retrieval time, code, official code, dates, title, related paths, and hashes;
7. skips every artifact whose manifest entry and bytes already verify; and
8. retains every unresolved row and secondary URL in the registry.

The retry action touches only unresolved discovery rows, so a portal failure
cannot discard verified work. A final serialized retry eliminated transient
errors and left 57 stable `official_not_found` results. That status means the
instrument was not recovered from the searched Government portal classes by
exact-code or title search; it is bounded acquisition residue, not proof that no
official copy exists anywhere.

## Deterministic storage

New artifacts use paths derived only from effective date and normalized code:

```text
data/raw/legal/ward/2026-04-30/237-nq-ubtvqh16.metadata.html
data/raw/legal/ward/2026-04-30/237-nq-ubtvqh16.original.pdf
```

The new originals comprise 159 PDF, 106 DOC, 92 RTF, and one HTM file; the 358
paired metadata records are HTML. They remain verbatim rather than gzip-wrapped.
This keeps the Government-published file directly inspectable and makes the
manifest SHA-256 describe the published object itself. Git still compresses its
object transport; the deterministic gzip contract remains appropriate for the
much larger repeated SOAP XML payloads, not these already compact or legacy
binary originals.

Seven legacy originals demonstrate why content validation is required: four
`.rtf` URLs contain OLE Word bytes, while three `.doc` URLs contain Word-oriented
HTML. The cache preserves the published suffix and bytes while the manifest
records both `declared_media_type` and `detected_media_type`.
