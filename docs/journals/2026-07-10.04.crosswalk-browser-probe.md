# Crosswalk browser probe — Doi_Chieu_Moi.aspx (the lineage source)

Written 2026-07-10. Browser-automation probe of the one surface `curl` can't
reach (DevExpress WebForms). Continues `2026-07-10.03`. This is the
authoritative **old↔new lineage** source that snapshot-diffing can't fully
provide.

## What the page is

`Doi_Chieu_Moi.aspx` = "ĐỐI CHIẾU ĐƠN VỊ HÀNH CHÍNH" (administrative-unit
comparison). It compares the admin hierarchy between **any two dates** at a
chosen level and shows, per unit, its counterpart on the other date **plus the
decree and a prose description of the change**.

Controls: **Cấp** (level: Tỉnh / Huyện / Xã), **Ngày gốc** (base date),
**Ngày đối chiếu** (comparison date), **Tỉnh** filter (sub-province levels),
**Có thay đổi** (changed-only checkbox), **Thực Hiện** (run), **Excel** (export).

## Columns (the payload)

Base side ↔ comparison (ĐC) side, per row:

- Base: `Tỉnh`/`Xã` code, name (`Tên …`), `Nghị định`, `Ngày hiệu lực`.
- ĐC: `Tên … ĐC`, code `… ĐC`, `Nghị định`, `Ngày hiệu lực`, `Tên Tỉnh ĐC`,
  `Tỉnh ĐC`.
- **`Ghi Chú`** — prose describing the exact change, naming the merged units and
  noting tier abolition, e.g. *"Hợp nhất xã Gia Mô, Lỗ Sơn … thành xã mới … xã
  Toàn Thắng.. Bỏ cấp huyện"* (merge these communes into new commune Toàn Thắng;
  abolish district tier).

Each row carries the **Nghị quyết number + date** (e.g. `202/2025/QH15 -
12/06/2025`, `1656/NQ-UBTVQH15 - 16/06/2025`, `1657/NQ-UBTVQH15`) and the
**effective date** (`Ngày hiệu lực`, e.g. `01/07/2025`). So this single view
merges crosswalk + decree catalog + effective dates + a composition narrative —
richer than diffing SOAP snapshots (which gives codes appearing/disappearing but
not the explicit many-to-one mapping, the decree, or the prose).

## Behaviors observed

- **Full outer join.** With base = current (10/07/2026) vs comparison =
  30/06/2025 at Tỉnh level: surviving/merged current provinces show with their
  counterpart; **absorbed old provinces appear as blank-base rows** (e.g.
  `Tỉnh Hà Giang` `02`, `Tỉnh Bắc Kạn` `06` — absorbed, no current same-name).
  So one query covers both sides of a transition.
- **Direction matters for merges.** base=new / comparison=old shows each current
  unit's *primary* predecessor (one row) + absorbed units as blank-base rows.
  To capture many-to-one merges cleanly (every old unit → its new unit), run
  **base=old / comparison=new**. Ingest should pull the old→new direction (and
  can use "Có thay đổi" to get only changed units = the lineage edges).

## Validated: the A1 code-reassignment case

At Tỉnh level, base 10/07/2026 vs comparison 30/06/2025:

- **current `15` "Tỉnh Lào Cai" ↔ comparison "Tỉnh Lào Cai" code `10`.**

So the crosswalk maps current Lào Cai to the *old Lào Cai* (code `10`) by
name/territory — while SOAP (`.02` A1) showed current code `15` was **Yên Bái's**
old code. Together: the merged province is named Lào Cai, carries the code `15`
that used to be Yên Bái's, and the crosswalk correctly links it to old Lào Cai
(`10`) — resolving the reassignment that would wreck a naive `MaTinh` join. This
concretely confirms the crosswalk is the authoritative lineage resolver the
`local_id` spine needs.

## Data-access mechanism

DevExpress ASP.NET WebForms. Pagination and "Thực Hiện" fire **POST callbacks to
`Doi_Chieu_Moi.aspx`** (viewstate/`__CALLBACKPARAM`-driven) — confirmed via
network capture (POST to the same URL; no XHR/JSON/REST endpoint). So bulk
extraction options are:

1. **Excel export** ("Excel" button) — cleanest full dump per (level, date-pair,
   filter). It is a **download** → requires user permission; schema to be
   confirmed from one permitted export at implementation time.
2. **Replay the DevExpress callback POST** with `__VIEWSTATE` + grid callback
   params, paging through results — scriptable but brittle.

Recommendation: at build time, drive the **Excel export** (level ∈ {Tỉnh, Xã},
base=old boundary date, comparison=new, changed-only) to get the lineage edges +
decree + effective date + notes in a few files; fall back to callback replay if
export is impractical.

## Resolved / newly open

Resolved: the crosswalk shape and richness; that it supplies decree references +
effective dates inline (so a separate `NghiDinh.aspx` pass may be unnecessary);
**public access — the page paginated and ran queries fully unauthenticated**, so
`Login.aspx` does not gate this data.

Newly open / deferred to build:
- Confirm the **Excel export schema** (needs a permitted download).
- Left-menu siblings not probed: `Chuyển đổi ĐVHC mới-cũ` (new↔old convert),
  `Nghị định` (decree catalog), `Lịch sử đơn vị HC`, `Tổng hợp ĐVHC`,
  `Thống kê số lượng`, `Địa bàn` — likely redundant with the crosswalk + SOAP,
  verify before relying on any.
- Whether the prose `Ghi Chú` is parseable enough to auto-derive edges, or is
  best kept as a human-readable reference alongside the code↔code mapping.

## Net picture for ingest

- **Snapshots (membership, all tiers, any date):** SOAP `DenNgay`, 1 call/tier/date.
- **Lineage edges (old↔new) + decree + effective date + notes:** `Doi_Chieu_Moi`
  Excel export, old→new, changed-only.
- **Identity spine:** repo-owned `local_id`, `(code, era)` keys — the crosswalk
  is how edges are established, never code equality.
