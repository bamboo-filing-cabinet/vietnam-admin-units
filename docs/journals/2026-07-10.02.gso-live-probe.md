# GSO live probe — SOAP service exercised end-to-end

Written 2026-07-10. Follow-up to `2026-07-10.01` (desk reconnaissance). This
time the live service was actually called from code (`curl` / `urllib`), so the
shapes below are **observed**, not inferred.

## Headline

The `DMDVHC.asmx` SOAP service is **time-parameterized**: every method takes a
`DenNgay` ("as-of date") and returns the administrative hierarchy **as it stood
on that date**. Verified: provinces come back **34 today vs 63 as of 2021**.
This is stronger than `2026-07-10.01` assumed — point-in-time snapshots at all
three tiers come straight from the SOAP service, so we do **not** need to scrape
the Lịch Sử page for historical membership. Lịch Sử / Đối Chiếu drop to a
*lineage-corroboration* role (Nghị quyết references, explicit old↔new mapping).

## Canonical host

- `https://danhmuchanhchinh.nso.gov.vn/` — **live** (HTTP 200).
- `https://danhmuchanhchinh.gso.gov.vn/` — **times out** (connection timeout).

Use `nso.gov.vn`. The `gso.gov.vn` host in the ecosystem docs is stale (the
GSO → National Statistics Office rename).

## Method contracts (from WSDL, confirmed by live calls)

Namespace `http://tempuri.org/`. SOAP 1.1 POST, `Content-Type: text/xml;
charset=utf-8`, `SOAPAction: "http://tempuri.org/<Method>"`. Date format
`dd/mm/yyyy` (e.g. `10/07/2026`).

| Method | Parameters | Returns |
| --- | --- | --- |
| `DanhMucTinh` | `DenNgay` | provinces as of date |
| `DanhMucQuanHuyen` | `DenNgay`, `Tinh`, `TenTinh` | districts under a province |
| `DanhMucPhuongXa` | `DenNgay`, `Tinh`, `TenTinh`, `QuanHuyen`, `TenQuanHuyen` | wards under a province/district |

`Tinh` / `QuanHuyen` take the **code** (`MaTinh` / `MaQuanHuyen`); the `Ten*`
variants are name-based alternatives (untested — code-based is what we'll use).
`QuanHuyen=""` (empty) is valid and returns all wards of the province directly —
the post-reform 2-level access path (see below).

### Response format

.NET `DataSet` serialized as an inline `xs:schema` + `diffgr:diffgram`. Each row
is a `<TABLE>` element. Field names per tier:

- **Province** (`DanhMucTinh`): `MaTinh`, `TenTinh`, `LoaiHinh` (e.g. "Thành phố
  Trung ương" / "Tỉnh"), `LoaiDoThi`, `Vung` (region).
- **District** (`DanhMucQuanHuyen`): province fields + `MaQuanHuyen`,
  `TenQuanHuyen`.
- **Ward** (`DanhMucPhuongXa`): the above + `MaPhuongXa`, `TenPhuongXa`,
  `LoaiHinh` (Phường/Xã/…), `LoaiDoThi`, `Vung`, `TThi_NThon` (urban/rural),
  `KhuVuc` (zone/area).

Parse with a diffgram-aware reader (rows = `<TABLE>`; read the embedded
`xs:schema` for field order). Codes are zero-padded strings ("01", "00004") —
keep them as strings, never ints.

## Verified behaviors

**`DenNgay` time-travel — works.**

| Query | Result |
| --- | --- |
| `DanhMucTinh(10/07/2026)` | **34** provinces (post-reform) |
| `DanhMucTinh(01/06/2021)` | **63** provinces (pre-reform) |

**District tier across the reform.** Scoped to Hà Nội (`Tinh=01`):

| Query | Result |
| --- | --- |
| `DanhMucQuanHuyen(2021, Tinh=01)` | **30 rows** — the real pre-reform districts |
| `DanhMucQuanHuyen(current, Tinh=01)` | **1 row = the province echoed back** (`MaQuanHuyen=01`, `TenQuanHuyen=Thành phố Hà Nội`, `LoaiHinh=Thành phố Trung ương`) |

So post-reform the district method returns a **pseudo-district that is the
province itself** (the tier is collapsed, not empty). Ingest must detect and
drop this (rule: post-reform, a "district" whose `MaQuanHuyen == MaTinh` is the
province stand-in, not a real unit).

**Ward tier post-reform (2-level, direct).** `DanhMucPhuongXa(current, Tinh=01,
QuanHuyen="")` → **126 wards** of Hà Nội, e.g. `00004 Phường Ba Đình`. Confirms
province→ward with no district in between.

## Ingest recipe (per era)

- **Pre-reform (3-level):** `DanhMucTinh(d)` → 63 provinces; for each,
  `DanhMucQuanHuyen(d, Tinh)` → districts; for each,
  `DanhMucPhuongXa(d, Tinh, QuanHuyen)` → wards.
- **Post-reform (2-level):** `DanhMucTinh(d)` → 34 provinces; for each,
  `DanhMucPhuongXa(d, Tinh, QuanHuyen="")` → wards directly. Skip
  `DanhMucQuanHuyen` (returns the province echo).

Detect the era by the province count (or by the `MaQuanHuyen == MaTinh` echo),
not by a hard-coded date, so the pipeline stays correct if GSO adjusts things.

## Building the temporal graph from this

`DenNgay` gives a snapshot at any date, so:

1. Snapshot a small set of **boundary dates** — just before/after each reform
   plus current (e.g. `01/06/2021`, `11/06/2025`, `02/07/2025`, today). Exact
   effective dates come from Lịch Sử / Nghị quyết (the reform took effect
   1 July 2025; the enabling resolution `202/2025/QH15` is dated 12/06/2025).
2. **Diff consecutive snapshots** → derive `valid_from` / `valid_to`
   (appearance/disappearance) and candidate lineage (a code vanishing while
   others appear in its territory).
3. **Corroborate lineage** against Lịch Sử / Đối Chiếu for the authoritative
   `merged_into` / `split_from` edges + Nghị quyết references — rather than
   guessing from name/territory overlap.

## Historical coverage — how far back `DenNgay` goes

Probed `DanhMucTinh` across a wide date range. **The floor is ~2001, not the
1945 founding.** Pre-floor dates return **0 rows** (empty), not an error — so it
is a data-availability floor (digitized from ~2001), not a modeled start of
administrative history.

**Exact floor (binary-searched to the day): `2002-01-01`.** `2001-12-31` → 0,
`2002-01-01` → 61, `2002-01-02` → 61. The round New Year's Day boundary — with
no matching administrative event (the 61-province state had existed since 1997) —
means this is GSO's **dataset epoch/baseline**, not a modeled change. Usable
range is exactly **2002-01-01 → present**.

Coverage regimes observed (dated as the *service* dates them):

| As-of date | Provinces | Real-world event |
| --- | --- | --- |
| ≤ 31/12/2001 | 0 (no data) | — (below the 01/01/2002 dataset epoch) |
| 01/01/2002 → 01/06/2004 | 61 | the 61-province state (in place since 1997) |
| 01/01/2005 → 01/07/2008 | 64 | 2003–04 splits (Điện Biên, Lai Châu, Đắk Nông, Hậu Giang) |
| 01/09/2008 → mid-2025 | 63 | Hà Tây merged into Hà Nội (Aug 2008) |
| current | 34 | 2025 reform |

~24 years of coverage (2001→now), spanning four province-count regimes — enough
for every NA term from NA11 (2002) onward; NA10 (1997) is at/below the floor.

**Caveat — the service's transition dating lags the legal dates.** The four
2003/2004 splits were legally effective 1 Jan 2004, but the service still
returns 61 through Jun 2004 and 64 only by 2005. So snapshot-diffing yields
GSO's *recorded* change dates, which may differ from the Nghị quyết effective
date. Anchor lineage edges to `NghiDinh.aspx` / Lịch Sử, not to the diff date.

**Boundary dates to snapshot** (refined): `01/01/2002` (61), `01/01/2005` (64),
`01/09/2008` (63), a mid-span 63 date, `01/06/2025` (63, pre-reform), and today
(34). Bracket each province-count change with a before/after pair, then bisect
for the exact GSO transition date where a term's `P768` needs it.

## Lịch Sử surface (for the lineage step — not done yet)

`Lich_Su_Moi.aspx` is an ASP.NET **WebForms + DevExpress** page:
`__VIEWSTATE` / `__EVENTVALIDATION` present; level combo `cmbCap`; Excel-export
buttons `btnExcel` / `btnExcel_B` / `btnExcel_CD`. Scripting it means either
replaying the postback/DevExpress callback with viewstate, or driving the Excel
export — fiddly; a **browser-automation probe** is the likely approach.

Relevant sibling pages discovered in its markup:
- **`Doi_Chieu_Moi.aspx`** — "Đối chiếu" = the official **old↔new crosswalk**.
  Highest-value target for lineage edges. Probe next.
- `NghiDinh.aspx` — decrees/resolutions list (the Nghị quyết catalog).
- `DiaBan1.aspx` — địa bàn (area) lookups.
- `Login.aspx` — a login exists; confirm whether any history depth or export is
  gated (public calls above were unauthenticated and worked).
