# Ward Wikidata review-queue reduction

Date: 2026-09-01

The first reconciliation snapshot left 926 of 3,321 current wards unassigned.
Two additional read-only evidence passes now reduce that queue to 651 without
weakening the collision or activity gates. No Wikidata writes or statement
files were produced.

## Predecessor-district tiebreak

The canonical graph already records every current ward's 2025 predecessor
composition. Former ward items on Wikidata commonly retain a `P131` pointing
to their abolished district. The district mapping can therefore distinguish
same-name candidates inside a newly merged province.

The matcher now uses that evidence only when:

- more than one candidate has already passed name, ward-class, current-province,
  and activity checks;
- exactly one candidate's district `P131` intersects the current ward's proved
  predecessor-district set; and
- the QID remains globally unique across assigned graph entities.

This resolves 114 current wards: 113 label matches and one alias match. The
shared Q10783690 Sông Trí/Kỳ Anh identity still fails the global collision gate
and remains unassigned.

## Saved broad-name discovery

The remaining 812 rows became the input to a second saved query:

- `queries/ward-wikidata-unresolved-names.rq` contains all 2,948 distinct
  Vietnamese and romanized search terms;
- `data/raw/wikidata/ward-unresolved-names-2026-09-01.sparql.json.gz` preserves
  the exact QLever response in deterministic gzip; and
- `data/ward-wikidata-unresolved-candidates.json` contains the compact
  normalized result, complete batched Action API evidence, and one review row
  per input ward.

The query SHA-256 is
`af379c8fbdafa2c3c682dde44534204b8adcf86e798424379a9af1f4efc27d1d`.
The stored gzip SHA-256 is
`caa610a36ce7bb84612dc255ea122319cebfce8af180e37c1a115d1ce93ab101`;
its exact 951,141 decoded bytes have SHA-256
`e05fabfda7db04a7e840c272fc3b90f67515f7867abaab9a8d21121a5bf813c4`.

The query intentionally has no `P31` restriction. It searches exact labels and
aliases so incorrectly typed or untyped items remain visible. It returned
4,964 bindings for 3,319 unique items; QLever reported 1,270 ms query time.

An initial query plan placed one `VALUES` block outside a label/alias `UNION`.
QLever then evaluated too much of both branches and the request ended at the
rate limit. Moving the same `VALUES` block inside each branch lets the index
constrain both lookups directly. A regression test now locks that two-block
shape.

All 3,319 returned QIDs were enriched through 67 `wbgetentities` batches of at
most 50. The reader requires every requested QID in each response, retries
JSON-level errors even when HTTP is 200, and uses a 30-second read-only
`maxlag` threshold to tolerate transient replica lag. The normalized evidence
includes labels, aliases, `P31`, `P131`, `P571`, `P576`, `P625`, Vietnamese and
English sitelinks, and revision metadata.

There are 631 rows with at least one item absent from the original direct
ward-class name candidate set. The 212 current-province non-ward matches are
mostly same-name former districts, towns, and cities whose `P576` is
2025-07-01. They are useful negative evidence and are not assigned to current
wards.

Broad candidates are assigned only when there is one preferred item after all
of these checks:

- an exact Vietnamese full or tierless term match, not only a romanized match;
- a `P131` resolving to the current province;
- an active ward-class `P31`; and
- when several active ward-class candidates remain, exactly one has the
  current graph tier.

This produces 162 proposals. One is rejected because Q10827242 is already
assigned to current Tiên Điền and also appears as an alias candidate for Nghi
Xuân. The other 161 are collision-free assignments.
