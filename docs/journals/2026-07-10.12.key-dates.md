# Key dates — glossary + which date is used where

Written 2026-07-10. Clears up the several distinct dates in play (they look
similar and get confused): the **2002 data floor**, the **2025 reform**, the
**pre/post snapshot dates**, and **today**.

## Quick answer: do we have data back to 2002-01-01?

**Yes — the full hierarchy, at all three tiers.** Verified live via SOAP
`DenNgay`:

| As-of date | provinces | districts | wards |
| --- | --- | --- | --- |
| **31/12/2001** | 0 | — | — |
| **01/01/2002** | **61** | **626** | **10,541** |

So 2002-01-01 is the earliest date with any data, and it already has the
complete province→district→ward tree. Nothing before it returns rows. This is a
**digitization floor / dataset epoch**, not a real administrative event (the
61-province structure had existed since 1997; see `.02`). Chained historical
modeling can therefore go back to 2002 in full — covering NA11 (2002) onward;
NA10 (1997) sits below the floor.

## ⚠️ Province stability ≠ hierarchy stability (2008–2025)

The timeline below lists only **province-level** events, so it can look like
"nothing happened between 2008-08-01 and the 2025 reform." **That is false for
the lower tiers.** Only the province *count* held at 63 (plus Huế's ~2025-01-01
city upgrade). Districts and wards churned constantly:

| date | provinces | districts | wards |
| --- | --- | --- | --- |
| 2008-09-01 | 63 | 685 | 11,047 |
| 2013-01-01 | 63 | 701 | 11,162 |
| 2017-01-01 | 63 | 714 | 11,181 |
| 2021-01-01 | 63 | 706 | 10,633 |
| 2025-06-30 | 63 | 696 | 10,035 |

Wards rose to ~11,181 then fell to ~10,035 — the ~1,100-commune drop is the
**2019–2024 commune-merger programs** (`sắp xếp ĐVHC cấp xã`), *before* the 2025
reform. And these are **net** counts; the number of actual change events (merge,
split, rename, upgrade, re-parent) is much larger. So the "all reforms, chained"
scope (`.11`/DESIGN) really means capturing **thousands of lower-tier events**
via Lịch Sử + snapshot diffs — the province timeline is the tip of the iceberg.

## The dates, and what each one is

| Date | What it is | Real event? |
| --- | --- | --- |
| **2002-01-01** | GSO **dataset epoch** — earliest data (61/626/10,541) | No (digitization floor) |
| **2004-06-30** | Service's date for the 2003/04 province splits (61→64) | Yes, but service-dated (legal date was ~1 Jan 2004; see `.02` A4) |
| **2008-08-01** | Hà Tây merged into Hà Nội (64→63) | Yes (matches legal date) |
| **2025-06-12** | Nghị quyết **202/2025/QH15** (enabling resolution) signed | Decree date |
| **2025-06-16** | Per-province NQ dates (`1656…/NQ-UBTVQH15` etc.) signed | Decree date |
| **2025-06-30** | **Last day of the OLD (63-province) structure** | Derived boundary |
| **2025-07-01** | **2025 reform EFFECTIVE date** (63→34; district tier abolished) | Yes — the event |
| **2026-04-30** | Đồng Nai upgraded to centrally-run city (6→7 cities) | Yes (type change) |
| **2026-07-10** | **Today** (this working session) | Now |

Note on years: the **reform is 2025**, **today is 2026**. A "2025-07-10" would be
a typo — our pipeline uses `2026-07-10` (today) and `2025-07-01`/`2025-06-30`
(the reform boundary). No date `2025-07-10` appears anywhere.

## Why the three similar dates differ (the actual confusion)

- **2025-06-30** = the **last day the old structure was valid** → we snapshot
  this to capture the pre-reform (63-province) state. It's a *boundary*, one day
  before the reform.
- **2025-07-01** = the **first day the new structure is valid** (reform took
  effect) → this is the *event date* stamped on Wikidata statements
  (dissolution `P576`, inception `P571`, effective-date qualifier `P585`).
- **2026-07-10** = **today** → we snapshot this to capture the *current* state
  (34 provinces, and it already includes the 2026-04-30 Đồng Nai change).

Mnemonic: **06-30 = "before"**, **07-01 = "the event"**, **2026-07-10 = "now"**.

## Where each date is used in the Phase-1 pipeline

| Pipeline location | Date (as passed) | Why |
| --- | --- | --- |
| SOAP pre-reform snapshot `DenNgay` | `30/06/2025` | capture old 63-province state |
| SOAP current snapshot `DenNgay` | `10/07/2026` | capture current 34-province state |
| Crosswalk **base** date (`Ngày gốc`) | `30/06/2025` | old side of the old↔new mapping |
| Crosswalk **compare** date (`Ngày đối chiếu`) | `10/07/2026` | new side |
| Entity `valid_to` (pre-reform) | `2025-06-30` | old entities end on the last old day |
| Entity `valid_from` (post-reform) | `2025-07-01` | new entities begin on the reform day |
| Lineage `effective_date` → `P576`/`P571`/`P585` | `2025-07-01` | the succession event date (= successor inception) |
| Statement reference (decree) | NQ dated `2025-06-12`/`-16` | the authority behind the change |

**Careful trap (fixed in code, `.11` / Task 10):** the crosswalk's per-row
`Ngày hiệu lực` is each unit's *own last-change date* (e.g. Yên Bái shows
`2004-06-30`), **not** the reform date. The pipeline deliberately uses the
successor's `valid_from` (`2025-07-01`) for the event date, never the base-row
`hieu_luc`.

## For future eras (chained model)

Each reform has its own trio: the **last-old-day** (snapshot boundary), the
**effective date** (event/statements), and the **decree date** (reference). The
2008 example: last-old-day 2008-07-31, effective 2008-08-01. Keep the three
roles distinct per reform; don't collapse "snapshot date" and "effective date".
