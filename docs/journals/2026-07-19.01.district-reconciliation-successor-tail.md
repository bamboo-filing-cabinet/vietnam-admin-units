Written 2026-07-19. The Phase-2 pre-upload audit (`reconcile.audit_district_qids`) caught that
the `wbsearchentities` **fallback** made wrong matches: it verifies only `P17=Vietnam`, **not
tier**, so for districts absent from the bulk district-tier pull it grabbed a same-named item of
any kind. This is the **maintainer decision list** for those 11. Until decided they are
`match_status='gap'` in `mappings/districts-qid.csv` (they emit **nothing** — the batch
`statements/na-districts.qs` = 707 clean districts; nothing wrong ships).

## Why they missed the bulk pull
Wikidata has **no district-tier item** for these (all 762 items in the 4 classes — huyện
`Q2582669`, quận `Q6644510`, thị xã `Q2112349`, thành phố thuộc tỉnh `Q3249005` — were searched
by folded name). In the 2025 two-tier reform each historical district became a ward / commune /
đặc khu, and WD re-modelled the place under the new unit. So there is no former-district item to
match; the choice per district is **successor-match** (Phú Quý-style), **create a new item**, or
**gap**.

## The 1:1 vs 1:many distinction (this drives the decision)
- **1:1 — island huyện → one đặc khu:** a single successor item exists → successor-match works
  cleanly (this is exactly the Phú Quý case, already decided → `Q32192913`).
- **1:many — mainland huyện → several wards:** no single successor item → successor-match has no
  clean target; realistic options are *create-new* or *gap*.

## Decision framework (pick per district, or one rule for the group)
- **Successor-match (Phú Quý-style):** set the successor QID + `verified`. ✓ Group 1 (islands) and
  Group 2 (with the *correct* ward). ✗ Group 3 (1:many — no single target).
- **Create new WD item:** the correct time-versioned model (own `P571`/`P131`/`P31`/`P576` +
  succession to the ward(s)). Needs QuickStatements `CREATE` support in `emit.py` (not built yet).
  Best fit for Group 3; would also let Phú Quý/islands be modelled cleanly if you prefer purity.
- **Gap (current state):** emit nothing. Safe default; revisit later.

## Modeling caveat (applies to successor-match incl. Phú Quý)
Matching to the successor puts `P576` "abolished 2025-07-01" on an item WD now models as a
still-existing ward/đặc khu — it reads as "this ward was abolished". Create-new avoids this. This
is the trade-off to weigh for Group 1/2 vs create-new.

## Systemic fix (so this can't recur)
`_district_search_fallback` / `match_districts` should verify the candidate is **district-tier**
(`P31 ∈ {Q2582669,Q6644510,Q2112349,Q3249005}`), not just `P17=Vietnam`. That would have rejected
all of these (→ honest gaps) instead of accepting wrong same-named items. A `verify_fn` returning
`P31` (or an added tier check) + a test update. Do before the next `reconcile_districts_live`.
