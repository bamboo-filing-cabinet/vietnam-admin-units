## Date discrepancies retained

Three date signals are present:

1. the pinned NSO legal index uses `2009-08-15`;
2. the Government page metadata and both original DOC headers use
   `2009-08-24`; and
3. the full-text transcription rendered inside the Government HTML says
   `2009-08-27`.

Article 2 of the original states that the resolution takes effect from the date
of signing. The derived provenance therefore records official issue/effective
date `2009-08-24`, while retaining the NSO index date as the instrument key and
the rendered `2009-08-27` text as a separate transcription discrepancy. The
registry fields are:

```text

issued_date=2009-08-24
official_effective_date=2009-08-24
effective_gap_days=-9
date_match_status=index_date_precedes_official_issue
effective_date_match_status=index_effective_date_differs
rendered_full_text_date=2009-08-27
rendered_full_text_date_match_status=differs_from_official_issue_date
```

No upstream value was rewritten or silently normalized.

## Reproducible recovery

`ward_legal_fetch.py --portal-recover` handles curated Government legal pages
that exact-code/title validation can identify even when the NSO date precedes
the official issue date. Ordinary portal discovery continues to reject
negative date gaps. The recovery path:

1. validates the official metadata code, title, issue date, and attachment
   URLs;
2. records the negative index-to-issue gap explicitly;
3. records any rendered full-text date that disagrees with page metadata;
4. downloads and signature-validates every original attachment; and
5. verifies all cached bytes through the raw manifest offline.

Commands:

```sh
uv run python -m vn_admin_units.ward_legal_fetch --portal-recover
uv run python -m vn_admin_units.ward_legal_fetch --fetch
uv run python -m vn_admin_units.ward_legal_fetch --check
uv run python -m vn_admin_units.ward_source_coverage --audit --open-note
uv run python -m vn_admin_units.ward_source_coverage --check --audit --open-note
uv run pytest -q
```
